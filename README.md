# Free Library - Blazor WASM + Vercel (Blob + Upstash Redis)

A Wikipedia-style PDF library. Frontend: Blazor WebAssembly (.NET 10), pure C#. Backend: two small
Vercel Functions (`api/download.js`, `api/stats.js`). PDFs live in a **private** Vercel Blob store.

## Folder structure

```
ebook-library/
├─ api/
│  ├─ download.js        GET /api/download?id=  -> count + 302 to a 5-minute signed Blob URL
│  ├─ stats.js           GET /api/stats         -> all download counts in one JSON object
│  └─ _catalog.json      id -> blob pathname (generated by the prepare script)
├─ scripts/
│  ├─ prepare-library.mjs  uploads PDFs to Blob + writes books.json and _catalog.json
│  └─ copy-site.mjs        copies the published Blazor wwwroot into ./public
├─ pdfs/                 put your 1,000 PDFs here (never deployed)
├─ public/               <- generated: the published Blazor site (this is what Vercel serves)
├─ src/WikiLibrary/      the Blazor project (never deployed, only built locally)
│  ├─ Models/Book.cs
│  ├─ Services/BookService.cs   loads books.json once; search/filter/sort/paging in memory
│  ├─ Layout/MainLayout.razor   header, search bar, sidebar, footer
│  ├─ Components/               BookList.razor, Pager.razor
│  ├─ Pages/                    Home, AzIndex, Categories, Category, Search, BookPage, ...
│  └─ wwwroot/                  index.html, css/wiki.css, logo.svg, data/books.json
├─ package.json  vercel.json  .vercelignore  .gitignore
```

What Vercel receives on `vercel deploy`: **`public/` + `api/` + `package.json` + `vercel.json`**
(`.vercelignore` keeps `src/`, `pdfs/`, `scripts/` out).

## Why you build locally

Vercel's build servers have no .NET SDK. So you run `dotnet publish` on your machine; the
published `wwwroot` is copied to `public/` and uploaded as plain static files.

## Deployment steps

Prerequisites: .NET 10 SDK, Node 22+, `npm i -g vercel`.

```bash
# 0. Install JS dependencies and log in
npm install
vercel login
vercel link                       # creates/links the Vercel project

# 1. Create the PRIVATE Blob store and link it to the project
vercel blob create-store free-library --access private --yes
#    (or: Dashboard -> Storage -> Create Database -> Blob -> Private -> connect to project)
#    This adds BLOB_READ_WRITE_TOKEN (and OIDC support) to the project.

# 2. Add Upstash Redis from the Marketplace
vercel integration add upstash/upstash-kv
#    (or: Dashboard -> Storage -> Create Database -> Upstash -> Redis -> connect to project)
#    It injects KV_REST_API_URL and KV_REST_API_TOKEN. The functions also accept
#    UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN.

# 3. Check / add environment variables (Production, Preview, Development)
vercel env ls
#    Needed: BLOB_READ_WRITE_TOKEN  and  KV_REST_API_URL + KV_REST_API_TOKEN
#    (if one is missing:  vercel env add NAME production)

# 4. Pull them locally so the prepare script can upload
vercel env pull .env.local

# 5. Put your PDFs in ./pdfs, then upload + generate books.json
npm run prepare-library
#    -> uploads to private Blob, writes src/WikiLibrary/wwwroot/data/books.json and api/_catalog.json
#    -> now open books.json and edit author / category / description / year / language / pages

# 6. Build the Blazor site into ./public
npm run build:site
#    (= dotnet publish src/WikiLibrary -c Release -o .publish  +  copy .publish/wwwroot -> public)

# 7. Deploy
vercel deploy --prod
```

After editing `books.json` later: run `npm run build:site` then `vercel deploy --prod` again.
Re-running `prepare-library` keeps ids and your hand edits and only uploads new PDFs.

## Local testing

`dotnet run --project src/WikiLibrary` serves the site (download counts and downloads need the API,
so they only work when deployed, or with `vercel dev` after `npm run build:site`).

## Notes

* books.json stores only `blobPathname`, never a storage URL.
* The signing token is store-wide for `get`, but every URL is signed for one pathname and expires in 5 min.
* If a download opens the PDF in a tab instead of saving it, that is normal browser behaviour for PDFs.
* Category names should not contain `/`.
* `_framework` is cached for a year as "immutable": .NET 10 fingerprints those filenames, so this is safe.
